# DevForge — статус разработки

Дата отчёта: 2026-10-28
Репозиторий: https://github.com/YarikBold/DevForge.git

## Выполнено

### Базовая платформа

- React + TypeScript + Vite.
- Тёмный интерфейс DevForge с боковой навигацией.
- SQLite-хранилище прогресса, попыток и черновиков.
- API для прогресса, экспорта, попыток и черновиков.
- Миграция базы данных при запуске.
- Экспорт прогресса через `/api/export`.
- Сохранение кода между перезапусками приложения.
- Production-сборка.

### Python и SQL

- Python-тренажёр с практическими заданиями и проверкой вывода.
- SQL-тренажёр с учебной SQLite-базой.
- Проверка успешных и неуспешных попыток.
- Тесты сохранения данных и миграций.

### Web Lab

- Редакторы HTML, CSS и JavaScript через Monaco Editor.
- Fallback-редактор, если Monaco не загрузился.
- Изолированный предпросмотр в sandbox iframe.
- Консоль сообщений и отображение ошибок JavaScript.
- Кнопки запуска, проверки и сброса.
- Сохранение Web Lab-черновиков и попыток.
- Проверка HTML через DOMParser.
- Проверка CSS и JavaScript по критериям заданий.
- Адаптивная компоновка.
- 214 уникальных заданий:
  - HTML — 44;
  - CSS — 53;
  - JavaScript — 117.
- Пять проектных спецификаций.
- Рабочее пространство «Мои проекты» с файлами `README.md`, `index.html`, `styles.css`, `app.js`.
- Предпросмотр проектов и проверка критериев.
- Раздел «Моё обучение» со статистикой успешных попыток и темами для повторения.

### C++

- Отдельный C++ Lab в интерфейсе.
- Monaco Editor с подсветкой C++.
- Поле stdin.
- Реальная компиляция через установленный `g++`.
- Выполнение программы во временном каталоге.
- Ограничение размера кода и stdin.
- Тайм-аут запуска.
- Отдельное отображение ошибок компиляции и вывода.
- Обработка бесконечного цикла.
- 120 учебных заданий C++.
- Серверный endpoint `/api/cpp/run`.
- Автоматические тесты успешной компиляции, ошибки компиляции и тайм-аута.

### PowerShell

- Отдельный PowerShell Lab в интерфейсе.
- Monaco Editor с подсветкой PowerShell.
- 85 учебных заданий PowerShell.
- Подсказки, критерии и стартовый код.
- Явное сообщение о недоступности `pwsh` в текущем окружении.
- Опасные команды не выполняются автоматически.

### Проверка качества

- `npm test` — 10 тестов проходят.
- `npm run build` — production-сборка проходит.
- `npm audit --omit=dev --audit-level=high` — уязвимостей нет.
- Playwright smoke-скрипт создан для проверки главной страницы и Web Lab.
- В GitHub отправлен коммит `015cc80`.

## Частично выполнено

### Web Lab и проекты

- Каталог заданий содержит критерии и стартовый код, но не каждое задание имеет отдельный скрытый runtime-тест.
- HTML проверяется структурно, но полноценная HTML-валидация ещё не подключена.
- CSS проверяется по правилам; вычисленные стили, координаты и переполнение пока не проверяются для каждого задания.
- Проектные рабочие пространства сохраняют файлы и запускают предпросмотр, но проверка критериев пока частично основана на требованиях и обязательных конструкциях.
- Менеджер задач и API-проект имеют спецификации, но не отдельные специализированные скрытые тестовые наборы.
- Аналитика прогресса работает на истории попыток, но не содержит полноценной модели навыков с уровнями освоения.

### C++

- В окружении есть `g++`, но нет `clang++`.
- `bwrap` доступен для обнаружения, однако runner использует fallback на временный каталог, если sandbox не запускается.
- Полная промышленная изоляция ресурсов, памяти, сети и системных вызовов ещё не реализована.
- Каталог заданий создан программно по темам; часть заданий требует индивидуального расширения входных наборов и скрытых тестов.
- C++ проекты имеют учебные темы, но ещё не выделены в отдельные рабочие проектные экраны.

### PowerShell

- `pwsh` и Windows PowerShell отсутствуют в текущем Linux-окружении.
- Реальное выполнение PowerShell не заявляется и не имитируется.
- Сейчас доступен редактор, каталог заданий и безопасное объяснение ограничений.
- Проверка PowerShell пока не является полноценным syntax/runtime runner.

### Браузерные тесты

- Playwright и Chromium использовались для smoke-проверки Web Lab.
- Полный набор браузерных тестов всех проектов, всех viewport-размеров и всех заданий ещё не создан.
- Monaco в headless-режиме иногда загружается нестабильно, поэтому оставлен fallback-редактор.

5. Разделить задания по этапам: теория, пример, самостоятельная работа, исправление ошибок, контрольная.
6. Добавить индивидуальные runtime-тесты для JavaScript DOM, событий, Promise, fetch и localStorage.
7. Добавить браузерную проверку CSS через computed styles, `getBoundingClientRect`, viewport 390/768/1440 и контроль горизонтального переполнения.
8. Добавить полноценную проверку HTML accessibility и валидности.
9. Расширить модель прогресса навыками, контрольными работами, повторением и уровнями освоения.

11. Добавить импорт резервной копии прогресса, сейчас реализован только экспорт.

13. Провести тестирование на чистой Windows 11 машине.
14. После реализации новых функций повторно запустить все тесты, сборку, аудит зависимостей и браузерные сценарии.
